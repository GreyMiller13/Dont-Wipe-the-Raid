# ADR-0001: Технологический стек

Дата: 2026-11-17 · Статус: принято

## Контекст

Инкрементальная 2D-игра (пиксель-арт) только под Android, один разработчик, 4–8 ч/нед. Опыт: C++, C#, HTML/CSS/JS, React, немного Python; опыта мобильной разработки и Unity нет. Цель проекта — в том числе освоить нативную разработку под Android и получить рабочий подписанный APK. Сохранение прогресса — локальное, серверной части нет. Приоритет бесплатных инструментов.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Kotlin + Jetpack Compose** | Официальный стек Android; цель «научиться нативной разработке» закрывается напрямую; всё бесплатное; полный контроль | Игровой цикл, анимации, спрайт-пайплайн — вручную; нет игрового редактора; часть готовых игровых абстракций придётся писать самому |
| Unity (C#) | Зрелый 2D-конвейер, редактор, анимации, ассет-стор; опыт C# | Не изучался; тяжёлый learnsink иruntime/APK; лицензионные условия; не закрывает цель нативного обучения |
| Godot | Лёгкий, бесплатный, хороший 2D | Новый язык (GDScript) и экосистема; то же не закрывает нативную цель |
| WebView + React | Знакомый стек | Производительность и «игровое ощущение» хуже; нативная цель не закрывается; гибридные костыли для звука/сохранений |

## Решение

**Kotlin + Jetpack Compose.** Решение пользователя 2026-11-17: Unity не изучался, приоритет — нативная разработка под Android.

## Последствия

- Рендер игры — Compose Canvas: собственный игровой цикл (coroutine/ticker), покадровая отрисовка спрайтов, анимации через спрайт-атласы.
- Инкрементальный жанр tolerantен к производительности: бои — небольшое число сущностей на экране, 30–60 FPS достижимы без OpenGL.
- Прототипы арта готовятся вне кода (пиксель-спрайты в ассетах), путь миграции в игру — через painter/imageBitmap.
- Риск: на анимациях и эффектах уйдёт больше времени, чем в игровом движке. Триггер пересмотра ADR — если боевой цикл стабильно проседает по FPS на целевом устройстве или анимационный конвейер съедает >30% времени разработки.
