# ADR-0002: Браузерный прототип с отложенным решением о платформе

Дата: 2026-11-18 · Статус: принято (замораживает ADR-0001 до решения по итогам MVP)

## Контекст

ADR-0001 (2026-11-17) выбирал стек для немедленной нативной разработки под Android. День арт-прототипирования (2026-11-17–18) показал: начинать с визуала нельзя — генерация арта съела два дня без прогресса в механиках. Пользователь перезапустил проект с новым порядком работ: сначала спека MVP-среза, затем ядро геймплея на программной графике, арт — пакетно в конце.

Цель ближайшего этапа — быстро валидировать механики (бой, прокачка, экономика, петля забега) с минимальной стоимостью итераций. При этом целевая платформа по-прежнему, в идеале, мобильная (Android); это решение сознательно откладывается до работающего MVP.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Kotlin + Compose сразу** (по ADR-0001) | Сразу нативный путь; нет портирования | Незнакомый стек замедляет итерации механик; медленный цикл «правка → запуск на устройстве»; риск снова уйти в полировку до валидации геймплея |
| **Браузерный прототип (HTML5 Canvas + чистый JS)** | Мгновенные итерации, нулевая установка; стек знаком; file:// без сервера; drag-n-drop/hover — нативно; тест в окне браузера; код переносим по логике | Не APK; мобильные API (звук, сейвы) отличаются; тач-сценарий отличается от мыши |
| **Unity/Godot** | Игровые абстракции | Новый стек и экосистема; тяжёлее, чем нужно для инкременталки на 30–60 FPS |

## Решение

**Прототип MVP делаем в браузере: HTML5 Canvas, чистый JavaScript без зависимостей, запуск с file://.** Решение пользователя 2026-11-18: код пишется с прицелом на мобильную платформу (логика — data-driven конфиги, отделённые от рендера), но решение об Android-порте принимается после того, как MVP подтвердит механики.

ADR-0001 не отменяется окончательно, а замораживается: если по итогам MVP выбирается нативный Android, он возвращается в силу для порта.

## Последствия

- **Архитектура:** разделение «симуляция (данные и правила боя) ↔ рендер (Canvas)»; числа баланса — в конфигах. Это делает возможным как Android-порт, так и PWA без переписывания логики.
- **Ввод:** прототип под мышь (hover-подбор лута, ЛКМ drag-n-drop навыков/зелий). Тач-сценарий (подбор касанием, перенос пальцем) фиксируется как требование при портировании.
- **Сохранения:** localStorage; при порте заменяется платформенным хранилищем.
- **Звук:** отсутствует в MVP (настройки — каркас); при появлении — Web Audio в браузере.
- **Триггер пересмотра:** MVP собран и играет → явное решение: нативный Android-порт (ADR-0001), PWA, или остаёмся в вебе.
